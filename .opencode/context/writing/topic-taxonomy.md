## Audience Skill Levels

### Beginner (Business User)
- **Assume**: Knows how to use software, may not code
- **Define**: Technical terms on first use
- **Show**: Step-by-step with screenshots, config-file-as-form approach
- **Explain**: The "why" — why this tool, why this approach, why it's better
- **Avoid**: Terminal commands without explanation, assumed programming knowledge

### Intermediate (Default — Builder)
- **Assume**: Comfortable with general tech concepts, may have basic coding
- **Define**: Domain-specific AI terms, not general programming
- **Show**: Focused code/config examples, skip boilerplate
- **Explain**: Tradeoffs, patterns, deployment options
- **Avoid**: Basic explanations of well-known concepts

### Advanced (Developer)
- **Assume**: Deep technical knowledge
- **Define**: Nothing unless it's a new or niche concept
- **Show**: Architecture, source code, benchmarks, failure modes
- **Explain**: Internal mechanics, performance characteristics, alternative approaches
- **Avoid**: Setup instructions, basic examples

## Calibration Rules
1. **Default to intermediate** unless topic or request specifies otherwise
2. **Adjust based on topic**: AI agent building leans intermediate-advanced, info product creation leans beginner-intermediate
3. **When in doubt, include a skill-level note at the top**
4. **Mixed audiences**: Write for intermediate, include "For non-technical readers" callouts and "Deep dive" sections for developers
5. **Every article should connect back to the core narrative**: ERP consultant → AI product builder
