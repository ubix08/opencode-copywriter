# E-E-A-T Signals for Technical Content

## Experience (Show You've Done It)

### Required Signals
- First-hand examples: "When I migrated our API from X to Y..."
- Screenshots of real implementations (not stock images)
- Terminal output from actual commands run
- Error messages encountered and how you resolved them
- Before/after comparisons with real data

### Implementation
- Use "I" or "we" for personal experience
- Include specific project context (company size, traffic, constraints)
- Show the messy middle, not just the polished result
- Mention what didn't work and why

## Expertise (Prove You Know It)

### Required Signals
- Author bio with relevant credentials or experience
- Links to prior articles on related topics
- Technical depth that demonstrates understanding
- Accurate version numbers, API references, and syntax
- Discussion of tradeoffs and edge cases

### Implementation
- Cite official documentation by name and version
- Reference specific RFCs, specs, or standards when applicable
- Explain the "why" behind recommendations
- Compare multiple approaches with honest pros/cons

## Authority (Back It Up)

### Required Signals
- 3+ statistics from credible sources per article
- Links to official docs, not third-party summaries
- Mentions of recognized tools, frameworks, or companies
- Data from benchmarks, surveys, or studies
- Attribution for all claims that aren't common knowledge

### Source Quality Rules
- Official documentation > blog posts
- Peer-reviewed or published data > anecdotal claims
- Recent sources (within 2 years) > outdated references
- Primary sources > secondary summaries
- Named authors > anonymous corporate content

## Trust (Be Transparent)

### Required Signals
- Publication date and last-updated date
- Clear methodology for any benchmarks or tests
- Disclosure of affiliations or sponsorships
- Correction policy or changelog for updates
- Honest discussion of limitations and uncertainties

### Implementation
- `datePublished` and `dateModified` in frontmatter
- "Tested on [date] with [tool versions]" notes
- "This article contains affiliate links" if applicable
- "Last tested: [date]" on code examples
- Acknowledge when information may be outdated

## Quick Checklist
- [ ] First-hand experience demonstrated (not just theory)
- [ ] Author credentials or background visible
- [ ] 3+ sourced statistics with links
- [ ] Official documentation cited
- [ ] Date stamps present (published + updated)
- [ ] Tradeoffs and limitations discussed
- [ ] No fabricated or unverifiable claims
- [ ] Code examples tested and versioned
